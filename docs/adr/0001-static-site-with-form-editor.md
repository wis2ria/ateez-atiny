# 0001：純靜態網頁，內容放在資料檔，用表單編輯器修改

日期：2026-11-15
狀態：已採用（同一天修訂過一次，見「修訂紀錄」）

## 背景

網站只有幾個部分（入坑必看、成員簡介、精選年表），用 GitHub Pages 免費架設。站主平日要上班，希望臨時想改推薦語或換影片時可以自己動手，不必每次都透過 Claude。站主不想直接編輯檔案，希望用表單來改。資料之後還要從精選版一路補成完整版。

## 決定

- 網站本身是最單純的靜態網頁（HTML、CSS、少量 JavaScript），不使用框架，沒有建置步驟。
- 所有內容（必看影片、推薦語、之後的成員和年表）集中放在 repo 裡的一個資料檔，和版面的程式碼分開。
- 站主透過「架在 repo 上的表單編輯器」修改內容：用 GitHub 帳號登入編輯頁面，填表單，儲存後由編輯器把內容寫回 repo 的資料檔，網站隨之更新。
- 內容的唯一來源仍然是 repo 裡的資料檔。編輯器只是一層介面，不另外存一份資料。
- 也可以交給 Claude 直接改資料檔。

## 具體工具

候選是 Pages CMS。安裝前要先確認：目前是否仍在維護、是否免費、登入時向 GitHub 要求的授權範圍（是否能只授權這一個 repo）。確認結果補在這裡。

## 考慮過但沒採用的做法

- **站主直接在 GitHub 網頁上編輯資料檔**：最初的決定。站主不想碰檔案，改為表單。
- **所有修改都透過 Claude**：每個小修改都要等。
- **用 Notion 當後台**：站主最熟悉，手機也能改；但要保管一組金鑰、多一個定時更新流程，修改不會馬上生效，出問題較難查。
- **獨立的內容管理服務**：對只有幾頁的網站太重，內容也會放在別人的服務上。

## 後果

- 多了一個外部工具要依賴。因為資料留在 repo，工具停止服務時資料不會遺失，換一個編輯器或回到直接改檔案即可。
- 需要寫一份編輯器的設定檔，描述表單有哪些欄位；之後每新增一種內容（成員、年表事件）都要跟著補設定。
- 編輯器需要 GitHub 授權。網站要求匿名，授權用的帳號和授權範圍要和「帳號名稱是否露出」的決定一起考慮。
- 如果之後頁面變多、需要每頁獨立網址，可能要改用靜態網站產生器，屆時資料檔和編輯器可以沿用。

## 修訂紀錄

- 2026-11-15：站主把編輯方式從「直接編輯資料檔」改為「用表單編輯器」，並在三種後台中選了架在 repo 上的表單編輯器。
